The LeviLamina carrier installs as a mod. The framework is the plugin manager; LeviLamina is its parent.

## Requirements

- Windows x64.
- Bedrock Dedicated Server 1.26.51 or newer, with LeviLamina 26.51 or newer installed and working.
- The .NET 10 runtime. The framework hosts the CLR inside the server process; without the runtime the startup sequence stops and says so in the log.

## Install

<Tabs syncKey="install">
  <TabItem label="Seiko">

```bash
sk init
sk add hosihikari-hosting-levilamina
```

`sk add` writes the declaration and syncs immediately: it installs `hosihikari-hosting-levilamina`, `hosihikari-hosting`, and the core `hosihikari`.

  </TabItem>
  <TabItem label="Release archives">

Download two archives from GitHub releases and extract both into the server root:

- `hosihikari-levilamina-windows-x64.zip` from the [HostingShim releases](https://github.com/HosihikariFramework/HostingShim/releases).
- `hosihikari-core-<version>.zip` from the [Core releases](https://github.com/HosihikariFramework/PluginManager/releases).

They write different files under `plugins/hosihikari/` and are meant to be merged. The HostingShim release notes name the compatible core line; the native shim checks the hosting-contract version at startup.

  </TabItem>
</Tabs>

Then start the server as usual.

## Verify

The server log should show the framework taking over:

- the CLR starts,
- the carrier registers with LeviLamina,
- LeviLamina enables it,
- the plugin manager reports the plugins it found under `plugins/`.

If none of that appears, the log line right after startup tells you why. See [Recovery](/framework/server/recovery/).

## Where things live

| Path | What |
| --- | --- |
| `plugins/hosihikari/` | The carrier, the plugin manager and its dependencies. |
| `plugins/<name>/` | Plugin packages. |
| `config/hosihikari/<name>.conf` | Server-side configuration overrides. |
| `data/hosihikari/<name>/` | Data the framework hands to each plugin. |
| `logs/latest.log` | Server and framework log. |

## Uninstall

Stop the server, then delete `plugins/hosihikari/`. Plugin packages live in `plugins/<name>/` and are removed separately. Configuration and data under `config/hosihikari/` and `data/hosihikari/` can be kept or deleted.
